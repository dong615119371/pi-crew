# 派活给船员（crew_async）

`crew_async` 把任务交给**后台的无头 pi 子进程**——它们跟你用同一套模型、技能、MCP 和 AGENTS.md，但**上下文是全新的，看不见你们这段对话**。作业由 async-jobs 引擎托管：有作业号、有日志、可杀、重启不丢。

## 角色从哪来

`~/.pi/agent/agents/*.md` 就是角色档案（worker / scout / planner / reviewer 是默认四个）。每个文件 frontmatter 里的 `tools`（工具白名单）和 `model`（专用模型）会被尊重；正文是角色人格。每次派活都会现读目录——改完角色文件，下一次派活立即生效。

## 派活纪律

1. **任务必须自包含**。船员看不见这段对话：目标、路径（绝对路径！）、期望的产出格式，全写进 task 里。
2. **只派体力活，不派决策**。批量修改、机械重构、重复检查、长_grunt work_。需要判断力的事自己做。
3. **fire-and-forget**。`crew_async` 调完立即返回作业号——继续干自己的活，或者**直接结束回合**。结果会作为新消息自己找来。
4. **不许轮询**。不要用 job_status 反复查；等待中的轮询浪费回合，结果到了自然会来。
5. **依赖它的活别异步派**。下一步必须用船员结果时，那一步自己做——异步没有"等它"的答案。
6. **不要把一次等待拆成两次**：先派活再干等，白白多一个来回。

## 选角色

| 默认角色 | 适合 |
| --- | --- |
| worker | 全能力执行：改文件、跑命令、交付产出 |
| scout | 只读侦察：找代码、摸结构、汇报压缩摘要 |
| planner | 出计划不动手 |
| reviewer | 只读审查：质量与安全问题 |

角色的 `tools` 白名单是硬约束（传给子进程 `--tools`），比嘴上嘱咐更可靠——**限制性任务优先选受限角色**，比如纯调研用 scout 而不是 worker。

## 模型怎么定

- 成员**默认跟随当前会话的模型**（你正在用的那个），不再用 pi 的默认模型——派出去的活成本和风格和你一致。
- 角色文件 frontmatter 里的 `model` 是更强的固定约束，会盖过上面的默认。
- **不推荐你自作主张换模型**：除非用户明确点名（"用 flash 跑"、"换 deepseek 查"、"用个小模型"之类），否则别动 `model` 参数。
- 用户明确要求时，在 `tasks[].model` 填 pi 的模型 id，格式 `provider/modelId`（如 `group/deepseek-flash`）；填错会当失败处理，原因随结果返回。

## 失败与刹车

- 作业失败时结果消息会带错误原因；同一任务重派前先想清楚为什么失败，**同一方案不重复派第二次**。
- 成员超时默认 30 分钟；确实的长活可以在参数里放宽。
- 成员里没有 crew_async（护栏 `PI_CREW_GUARD`）——**船员不能再派船员**，层级只有一层。
